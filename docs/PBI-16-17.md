## 1. Dua PBI yang dikerjakan

|---|---|---|
| **PBI-16 / KF-16** | Petugas verifikator dapat memeriksa detail pengaduan beserta rujukan pasal hasil pre-screening, lalu menetapkan apakah laporan valid untuk diproses, ditolak karena di luar kewenangan, atau memerlukan tambahan kelengkapan dokumen dari pelapor. | Verifikator melihat kronologi + hasil pre-screening + bukti; tiga keputusan; pelapor bisa mengirim kelengkapan; alasan penolakan terbaca pelapor. |

## 4. Kontrak data payload

Tambahan field bersifat **opsional dan backward-compatible**. Data lama tanpa field ini harus tetap tampil.

```json
{
  "id": "BHM-2026-0001",
  "status": "Menunggu Kelengkapan",
  "agency": null,
  "rejection_reason": null,
  "completeness_request": {
    "note": "Lampiran belum lengkap.",
    "documents": ["KTP", "Bukti pembayaran"],
    "requested_at": "2026-11-23T10:00:00+07:00",
    "requested_by": "Nama Verifikator",
    "fulfilled_at": null
  },
  "completeness_submissions": [
    {
      "date": "2026-11-23T11:00:00+07:00",
      "note": "Sudah saya lampirkan.",
      "attachments": [
        {"name": "ktp.pdf", "path": "complaints/BHM-2026-0001/abc.pdf", "mime": "application/pdf", "size": 12345}
      ]
    }
  ],
  "dispositions": [
    {
      "agency": "Inspektorat Daerah",
      "date": "2026-11-23T12:00:00+07:00",
      "note": "Diteruskan untuk pemeriksaan.",
      "by": "Nama Verifikator"
    }
  ],
  "follow_up": {
    "summary": "Instansi sudah menindaklanjuti dan memberikan sanksi administratif.",
    "attachment": {"name": "hasil.pdf", "path": "complaints/BHM-2026-0001/hasil.pdf", "mime": "application/pdf", "size": 23456},
    "updated_at": "2026-11-23T13:00:00+07:00",
    "by": "Nama Verifikator"
  },
  "attachments": [
    {"name": "bukti.jpg", "path": "complaints/BHM-2026-0001/bukti.jpg", "mime": "image/jpeg", "size": 34567}
  ]
}
```

Aturan:

- `completeness_request` diisi saat aksi `complete`; `fulfilled_at` diisi saat pelapor mengirim kelengkapan.
- `rejection_reason` diisi saat aksi `reject`.
- `dispositions` bertambah satu entri setiap aksi `dispatch` (saat ini hanya boleh sekali per siklus).
- `follow_up` diisi saat aksi `status` menyertakan ringkasan/berkas.
- `agency` tetap dipertahankan sebagai instansi disposisi terakhir agar halaman lacak lama tetap bekerja.
- `attachments` tetap array datar; kelengkapan susulan **ditambahkan** ke array yang sama, bukan mengganti.

## 5. State machine yang dikunci

```text
Baru
 ├─ verify ────────────────> Menunggu Disposisi
 ├─ complete ──────────────> Menunggu Kelengkapan
 │                              ├─ pelapor unggah kelengkapan ──> Menunggu Verifikasi
 │                              ├─ verify ─────────────────────> Menunggu Disposisi
 │                              ├─ complete (minta lagi) ───────> Menunggu Kelengkapan
 │                              └─ reject ─────────────────────> Ditolak
 └─ reject ────────────────> Ditolak

Menunggu Verifikasi
 ├─ verify ────────────────> Menunggu Disposisi
 ├─ complete ──────────────> Menunggu Kelengkapan
 └─ reject ────────────────> Ditolak

Menunggu Disposisi
 └─ dispatch (wajib agency) > Dalam Proses

Dalam Proses
 └─ status
      ├─ "Dalam Proses" (ringkasan opsional) ──> Dalam Proses
      └─ "Selesai" (wajib follow_up.summary) ──> Selesai
```

Aturan tambahan:

- `verify`, `complete`, `reject` hanya dari `Baru`, `Menunggu Verifikasi`, `Menunggu Kelengkapan`.
- `dispatch` hanya dari `Menunggu Disposisi`.
- `status` hanya dari `Dalam Proses`.
- `Ditolak` dan `Selesai` adalah terminal; tidak ada aksi lanjutan.
- Server wajib menolak transisi yang tidak sah, bukan hanya menyembunyikan tombol di UI.

## 12. Risiko residual yang harus disadari

1. **Nomor tiket berurutan dan mudah ditebak.** Siapa pun yang menebak tiket bisa melihat status dan mengunggah kelengkapan. Mitigasi saat ini: throttle, validasi status, validasi berkas, penyimpanan privat, tanpa unduhan publik. Jika ingin lebih kuat, token akses acak perlu ditambahkan di masa depan (bukan scope PBI ini).
2. **Berkas yatim.** Jika transaksi database gagal setelah berkas disimpan, berkas bisa tertinggal di disk. Kebijakan retensi/cleanup belum ada; catat sebagai utang teknis.
3. **Payload JSON bukan model domain penuh.** Query dan validasi berbasis JSON akan makin sulit saat PBI-18 butuh rekap. Jangan menambah kompleksitas baru di JSON; jika perlu, migrasi ke tabel domain dibahas terpisah.
4. **Riwayat lama di halaman lacak** bisa menampilkan teks panjang karena entri lama tidak memakai pemisah `·`. Jangan perbaiki di PBI ini kecuali diminta; fokus pada entri baru.
